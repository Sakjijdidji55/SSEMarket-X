## 1. 升级的“坏处”总览

在逐页方案之前，先把代价说清楚。这些坏处是全局的，后面每一页还会写它自己的坏处。

### 1.1 两套前端会同时存在

- Vue 主站还要继续跑，小程序在 Web 端也还要用；
- Flutter 再写一套，等于同一个功能维护两份；
- 两边的接口、字段、活动规则一变，要同步改两处；
- 如果只改 Flutter 不改 Vue，用户会发现 App 和网页不一样。

**缓解**：先升级 App 入口，Vue 页面保留给 Web；在功能开关里明确“App 走原生，Web 走 Vue”，不要试图让两边代码完全共用。

### 1.2 失去“改完就生效”的便利

- Vue 页面部署后用户刷新就能用；
- Flutter 页面要发版，Android/iOS/鸿蒙/桌面都要重新打包；
- 紧急修 bug 受应用商店审核影响。

**缓解**：非关键逻辑放服务端或功能开关；原生页面只做展示和交互，业务规则尽量后端化。

### 1.3 App 会变大

- 新增音频后台、PDF、文件选择、视频播放等插件；
- 安装包会比现在大；
- 低端机内存占用可能上升。

**缓解**：按需加载、拆分 ABI、移除不用的依赖、图片/音频走缓存。

### 1.4 平台差异会变多

- Android/iOS/鸿蒙/Windows 的系统能力不一样；
- 后台播放、PDF 预览、文件选择、通知在各平台表现不同；
- Windows/鸿蒙可能需要平台通道（MethodChannel：Flutter 和原生代码之间的桥）。

**缓解**：做平台矩阵，先保证 Android/iOS，再补鸿蒙/Windows；不支持的能力保留 WebView 兜底。

### 1.5 样式“一模一样”有上限

- 字体渲染不同；
- CSS 毛玻璃、复杂动画、混合模式要重写；
- 浏览器滚动和 Flutter 滚动惯性不同；
- 安全区、状态栏、键盘避让不同。

**现实目标**：90%–95% 视觉一致；追求 100% 像素一致会陷入无底洞。

### 1.6 测试成本上升

- 每个页面要测加载、空、错误、分页、登录过期、弱网；
- 阅读器/播放器/PDF 要真机测试；
- 要多端截图对比。

**缓解**：先做组件库和 golden test（截图对比测试），不要让每页重复造轮子。

## 2. 公共底座（第 0 期，必须先做）

逐页升级前，先把这些做好，否则每页都会写一遍重复代码。

### 2.1 设计 token（设计变量）

“token”在这里不是登录凭证，而是颜色、字号、间距、圆角、阴影的统一定义。

#### 从 Vue 现有样式抽取的基础值

| 类别 | Vue 现有值 | Flutter 对应 |
|---|---|---|
| 页面背景 | `#f4f6f8` / `#f5f6f7` / `var(--color-bg)` | `AppColors.pageBg` |
| 卡片背景 | `#fff` / `var(--color-card)` | `AppColors.card` |
| 主文字 | `#1e293b` / `#0f172a` | `AppColors.textPrimary` |
| 次文字 | `#475569` / `#64748b` | `AppColors.textSecondary` |
| 弱文字 | `#94a3b8` / `#9ca3af` | `AppColors.textMuted` |
| 强调色（小说） | `#2c3d56` | `AppColors.novelAccent` |
| 强调色（媒体） | `#ec4141` | `AppColors.mediaAccent` |
| 强调色（视频） | `#0f766e` | `AppColors.videoAccent` |
| 圆角 | 8 / 10 / 12 / 14 / 16 / 20 / 999 | `AppRadii.*` |
| 媒体首页背景 | `#f4f6f8` | `AppColors.mediaBg` |
| 媒体 hero 渐变 | `#111827 → #2b1b3d → #4a1d3d` | `LinearGradient` |
| 卡片阴影 | `0 3px 12px rgba(15,23,42,.04)` | `BoxShadow` |

#### Flutter 落地方式

```dart
// 示意：实际写在 lib/shared/theme/app_tokens.dart
class AppColors {
  static const pageBg = Color(0xFFF4F6F8);
  static const card = Colors.white;
  static const textPrimary = Color(0xFF1E293B);
  static const textSecondary = Color(0xFF475569);
  static const textMuted = Color(0xFF94A3B8);
  static const novelAccent = Color(0xFF2C3D56);
  static const mediaAccent = Color(0xFFEC4141);
  static const videoAccent = Color(0xFF0F766E);
}

class AppRadii {
  static const r8 = 8.0;
  static const r10 = 10.0;
  static const r12 = 12.0;
  static const r14 = 14.0;
  static const r16 = 16.0;
  static const r20 = 20.0;
  static const pill = 999.0;
}
```

**注意**：不要在每个页面写 `Color(0xFF...)`，否则后面改主题要全库搜索。

### 2.2 字体策略（影响“像不像”的关键）

Vue 用的是系统字体栈：

```text
-apple-system, BlinkMacSystemFont, "Segoe UI",
"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei",
"Helvetica Neue", Helvetica, Arial, sans-serif
```

Flutter 默认字体是 Roboto，中文会走系统回退，字号和字重看起来会不一样。

**方案 A（推荐，体积小）**：不打包字体，设置 `fontFamilyFallback` 为平台中文字体：

```dart
TextStyle(
  fontFamilyFallback: const [
    'PingFang SC',      // iOS/macOS
    'Microsoft YaHei',  // Windows
    'Noto Sans CJK SC', // Android/Linux
    'Source Han Sans SC',
  ],
)
```

**方案 B（最像，体积大）**：打包一份 `Noto Sans SC` 或 `Source Han Sans SC`，全端统一。代价是 APK 增大 3–8MB。

**建议**：先方案 A，逐个页面截图对比；如果中文标题/正文差异明显，再换方案 B。

### 2.3 组件库

在 `lib/shared/components/native/` 下建一套和 Vue 对齐的组件：

| Vue 组件/样式 | Flutter 组件 |
|---|---|
| `.novel-page__btn` | `NovelButton`（primary/ghost） |
| `.novel-card` | `NovelCard` |
| `.resume-page__tab` | `PillTab` |
| `.ranking-page__podium` | `Podium` |
| `.video-grid` | `VideoGrid` |
| 卡片阴影 | `AppCard`（统一 `BoxDecoration`） |
| 骨架屏 | `SkeletonBox`（已有可复用） |
| 空状态 | `EmptyState` |
| 错误重试 | `ErrorRetry` |

### 2.4 API 与状态

- 统一 `ApiClient`：超时、重试、401 刷新、错误码；
- 统一分页模型：`PageResult<T> { items, total, hasMore, offset }`；
- 页面状态用 `StatefulWidget + setState` 或 `ChangeNotifier`，不要每页引入新框架；
- 复杂页面（阅读器/播放器）单独建 `Controller`。

### 2.5 本地存储

| 数据 | 方案 |
|---|---|
| 阅读进度、字号、主题 | `SharedPreferences` |
| 小说章节缓存、草稿、任务记录 | `drift` 或 `sqflite` |
| 图片/音频缓存 | 文件缓存 + 索引 |
| 登录 token | `flutter_secure_storage` |

### 2.6 功能开关（Feature Flag）

“功能开关”= 远程配置，控制用户走原生页还是旧 Vue 页。

```text
novel_native = false → true（灰度）
media_native = false → true
resume_native = false → true
ranking_native = false → true
course_native = false → true
```

好处：新页面出问题可以一键切回旧页面；可以按用户/设备灰度；不用发版就能关闭问题功能。

### 2.7 测试与截图基线

- 先给每个 Vue 页面截两张图：手机 390×844、桌面 1440×900；
- Flutter 同尺寸截图；
- 用 golden test 对比，允许 2%–5% 差异（字体/抗锯齿）；
- 每个页面至少测：加载、空、错误、分页、登录过期。

## 3.1 小说：发现/书架页

**目标文件**：`lib/views/novel/novel_home_page.dart`  
**Vue 参考**：`src/views/NovelView.vue`

### 页面目标

- 用户进入小说模块的第一页；
- 「发现」看分类和推荐；
- 「我的书架」看收藏的小说；
- 搜索、分类筛选、分页加载。

### 现在有什么

- 顶部品牌/标题/搜索；
- 「发现 / 我的书架」Tab；
- 分类横向筛选；
- 小说卡片网格：封面、标题、作者、状态、字数/评分；
- 分页/加载更多；
- 空状态、骨架屏。

### 怎么升级

1. **路由**：`/novel`，由首页/小程序入口跳转；
2. **页面结构**：
   - `Scaffold` + `CustomScrollView`；
   - 顶部 `SliverAppBar`（标题、搜索、Tab）；
   - 分类用横向 `ListView` + `ChoiceChip`（选择标签）；
   - 小说列表用 `SliverGrid`（网格）；
3. **状态**：
   - `_tab`：discover/shelf；
   - `_category`、`_keyword`；
   - `_items`、`_offset`、`_hasMore`、`_loading`；
4. **API**：
   - `getNovels` → `/auth/novel/list`；
   - `getShelf` → `/auth/novel/shelf/list`；
   - `getNovelCategories` → `/auth/novel/categories`；
5. **缓存**：
   - 书架先读本地缓存，再后台刷新；
   - 发现页不缓存列表，只缓存分类；
6. **交互**：
   - 下拉刷新；
   - 滚动到底加载更多；
   - 点击卡片进详情；
   - 搜索防抖 300ms。

### 样式怎么对齐

| Vue 样式 | Flutter 做法 |
|---|---|
| `.novel-page` 背景/内边距 | `AppColors.pageBg` + `EdgeInsets` 14 |
| `.novel-page__brand` 14px、accent | `TextStyle(fontSize:14, color:novelAccent)` |
| `.novel-page__btn` 圆角 8、11px | `NovelButton` 统一 |
| 小说卡片封面比例 | 用 `AspectRatio` 固定封面比例，和 Vue 的 `aspect-ratio` 一致 |
| 卡片间距 | 用 Vue 的 `gap` 值直接映射到 `SizedBox`/`spacing` |
| 骨架屏 | 复用现有 `SkeletonLoader`，格子数量和 Vue `ContentSkeleton` 一致 |

**具体检查**：

- 卡片宽度、列数：手机 2 列，平板 3–4 列；断点和 Vue 的 `@media` 对齐；
- 封面圆角、阴影和 Vue 卡片一致；
- 标题最多 2 行，超出省略；
- 作者/状态字号 11–12px，颜色 `textSecondary`。

### 升级的坏处

- 书架缓存要做好，否则断网时反而比 Vue 更空；
- 分类接口和列表接口是两次请求，首屏比 Vue 多一次网络往返；
- 网格在不同屏幕宽度下列数变化，设计稿要补平板/桌面；
- 如果 Vue 页面继续保留，分类筛选逻辑要维护两份。

### 验收标准

- [ ] 发现/书架切换不白屏；
- [ ] 分类筛选、搜索、分页正常；
- [ ] 书架断网可显示缓存；
- [ ] 封面失败有占位；
- [ ] 手机 2 列、平板 3–4 列布局正常。

## 3.2 小说：详情页

**目标文件**：`lib/views/novel/novel_detail_page.dart`  
**Vue 参考**：`src/views/NovelBookView.vue`

### 页面目标

- 展示小说信息、章节、评论、评分；
- 加入/移出书架；
- 作者管理封面/删除小说；
- 进入阅读器/写作页。

### 现在有什么

- 封面、标题、作者、状态、字数、评分；
- 简介展开/收起；
- 章节列表（分页/加载更多）；
- 评论列表（最新/最热、搜索、点赞、删除）；
- 评分条、书架按钮；
- 作者上传封面、删除小说。

### 怎么升级

1. **页面结构**：
   - `CustomScrollView` + `SliverAppBar`（封面折叠）；
   - 头部信息卡；
   - 章节区 `SliverList`；
   - 评论区 `SliverList` + 底部输入框；
2. **API**：
   - `getNovelDetail`；
   - `getNovelChapters`；
   - `getNovelComments` / `createNovelComment` / `likeNovelComment` / `deleteNovelComment`；
   - `toggleShelf`、`rateNovel`、`deleteNovel`、`updateNovel`；
3. **交互**：
   - 收藏按钮乐观更新（先改 UI，失败回滚）；
   - 评分后立即显示新分数；
   - 评论点赞本地先加一；
   - 删除评论二次确认；
4. **封面**：
   - `image_picker` 选图；
   - 压缩后上传；
   - 上传中显示进度/禁用按钮。

### 样式怎么对齐

- 头部卡片：白底、`radius 8`、阴影 `0 3px 12px rgba(15,23,42,.04)`；
- 标题 18px/600，作者 13px `textSecondary`；
- 徽章 `radius 999`、11px；
- 章节行：左右 14px、上下 10–12px，底部 1px 分隔线；
- 评论区复用原生帖子评论组件，气泡/头像/时间字号和 Vue 对齐；
- 折叠封面用 `SliverAppBar` 的 `expandedHeight` 对齐 Vue 封面高度。

### 升级的坏处

- 评论和章节两个长列表放在一个页面，滚动嵌套要处理；
- 乐观更新在弱网下可能出现“先成功又回滚”的闪烁；
- 封面裁剪/压缩参数如果和 Vue 不一致，视觉会不同；
- 作者操作（删书、换封面）权限判断要重新做，容易漏。

### 验收标准

- [ ] 章节/评论分页正常；
- [ ] 收藏/评分/点赞即时反馈；
- [ ] 作者能换封面、删书；
- [ ] 删除评论有确认；
- [ ] 长列表滚动不卡。

## 3.3 小说：阅读器（重点）

**目标文件**：`lib/views/novel/novel_reader_page.dart`  
**Vue 参考**：`src/views/NovelReaderView.vue`

### 页面目标

- 阅读章节正文；
- 目录、上一章/下一章；
- 字号、行宽、主题；
- 阅读进度保存/上报；
- 长按选中、复制、段落评论。

### 现在有什么

- 顶部栏：返回、书名、章节名、目录、设置；
- 正文段落；
- 目录抽屉/弹层；
- 设置面板：主题、字号、行宽；
- 阅读进度心跳、阅读时长累计；
- 长按选择文字、复制、评论段落；
- 段落级评论。

### 怎么升级

#### 第一步：先做技术验证（POC）

在正式写页面前，先用 1–2 天验证三件事：

1. 长文本滚动是否流畅；
2. 跨段落选中是否可行；
3. 长按菜单能否自定义。

如果跨段落选中太难，退化为“按段落选择 + 段落评论”，不要死磕浏览器级选中。

#### 第二步：页面结构

```text
Scaffold
  ├─ 顶部栏（返回 / 书名 / 章节 / 目录 / 设置）
  ├─ 正文 ListView.builder
  │    └─ 每个段落一个 SelectableText / RichText
  ├─ 底部栏（上一章 / 进度 / 下一章）
  ├─ 目录 BottomSheet
  └─ 设置 BottomSheet
```

#### 第三步：正文渲染

- 按段落拆分，不要把整章塞进一个 `Text`；
- 用 `ListView.builder` 懒加载；
- 段落间距、首行缩进、行高用 token；
- 图片段落单独渲染；
- 章节切换时保留滚动位置。

#### 第四步：选中与长按

- 方案 A：`SelectionArea` 包住 `ListView`（简单，但跨段落行为受平台限制）；
- 方案 B：`SelectableRegion` + `contextMenuBuilder`（可自定义“复制/评论”）；
- 方案 C：段落级点击/长按，选中整段（最稳，推荐先做）。

#### 第五步：进度

- 本地存 `novelID + chapterID + offset`；
- 进入页面先恢复本地进度；
- 每 15–30 秒上报一次；
- `AppLifecycleState.paused` 时强制 flush（立即写入）；
- 退出页面时再 flush 一次。

#### 第六步：设置

- 主题：日间/夜间/护眼/羊皮纸；
- 字号：14–24；
- 行宽：窄/中/宽；
- 设置存 `SharedPreferences`，全局生效。

#### 第七步：目录

- 拉章节列表；
- 当前章节高亮；
- 点击跳转；
- 支持加载更多章节。

### 样式怎么对齐

| Vue | Flutter |
|---|---|
| `.novel-reader__bar` 白底、底部边框 | `AppBar`/自定义顶部栏，颜色 `card`，`borderBottom` 1px |
| 章节名 13px、书名 11px muted | 对应 `TextStyle` |
| 正文颜色 `--color-text #1e293b` | `AppColors.textPrimary` |
| 正文行高/段距 | 从 Vue 的 `line-height`/`margin` 直接映射 |
| 主题背景色 | 每个主题一组 `backgroundColor`/`textColor`，从 Vue 主题表复制 |
| 设置面板圆角/间距 | 与 Vue 底部面板一致 |
| 顶部按钮 8px 圆角 | `AppRadii.r8` |

**字体**：阅读器对字体最敏感。建议阅读器单独允许用户选字体（系统/宋体/黑体），默认跟随全局；如果 Vue 用的是系统字体，Flutter 也用系统回退。

### 升级的坏处

- 开发难度最高，跨段落选中/长按菜单是主要风险；
- 不同平台选中行为不同，要逐端测试；
- 长章节如果一次性渲染会卡，必须做懒加载；
- 进度上报太频繁会增加网络/电量消耗；
- 主题、字号、行宽组合多，测试矩阵大；
- 如果做不好，阅读体验可能暂时不如浏览器，需要 POC 先验证；
- 原生阅读器要自己处理“本章完/下一章”边界，容易漏。

## 4. 样式“尽量一模一样”的详细做法

### 4.1 先冻结截图

每个页面在 Vue 端截：

- 手机：390×844（iPhone 14 逻辑尺寸）；
- 平板：768×1024；
- 桌面：1440×900（如果页面支持）。

截图要包含：

- 加载中；
- 空状态；
- 错误状态；
- 正常列表；
- 弹窗/底部面板。

### 4.2 从浏览器 DevTools 抄数值

对每个关键元素记录：

- `color`、`background`、`border`、`border-radius`；
- `font-size`、`font-weight`、`line-height`；
- `padding`、`margin`、`gap`；
- `box-shadow`；
- `width`/`height`/`aspect-ratio`；
- 响应式断点。

不要凭感觉写“差不多 12px”，要抄准确值。

### 4.3 Flutter 端统一映射

| CSS | Flutter |
|---|---|
| `padding: 14px` | `EdgeInsets.all(14)` |
| `gap: 10px` | `SizedBox(height/width: 10)` 或 `Wrap(spacing:10, runSpacing:10)` |
| `border-radius: 8px` | `BorderRadius.circular(8)` |
| `box-shadow: 0 3px 12px rgba(...)` | `BoxShadow(color, offset, blurRadius)` |
| `font-size: 14px` | `TextStyle(fontSize: 14)` |
| `line-height: 1.7` | `height: 1.7` |
| `env(safe-area-inset-top)` | `MediaQuery.paddingOf(context).top` |
| `@media (min-width:768px)` | `LayoutBuilder` + 断点 |

### 4.4 字体与字号

- 先不打包字体，使用系统中文回退；
- 标题/正文用和 Vue 相同的字号、字重；
- 数字用 `FontFeature.tabularFigures()`（等宽数字），避免时长/积分跳动；
- 如果截图差异明显，再打包 Noto Sans SC。

### 4.5 圆角、阴影、渐变

- 圆角/阴影全部走 token；
- 渐变用 `LinearGradient`/`RadialGradient`，颜色停点和 Vue 完全一致；
- 毛玻璃用 `BackdropFilter`，但低端机要降级为半透明色。

### 4.6 图标

- Vue 用 Tabler/Iconify 的，Flutter 用对应 SVG；
- 不要混用 Material 图标，否则风格会明显不一致；
- 图标大小、颜色、线宽和 Vue 对齐。

### 4.7 滚动与手势

- Android 用 `ClampingScrollPhysics`，iOS 用 `BouncingScrollPhysics`；
- 下拉刷新用 `RefreshIndicator`；
- 长按/选中用平台习惯，但要保留“复制/评论”等业务菜单；
- 滚动位置在返回时恢复。

### 4.8 截图对比

- 每个页面做 golden test；
- 允许 2%–5% 差异；
- 重点看：标题位置、卡片间距、按钮高度、颜色、圆角、文字截断。

### 4.9 现实目标

- **90%–95% 视觉一致**：普通用户看不出明显差异；
- **100% 像素一致**：不可能，也不值得；
- 如果某些 CSS 效果成本太高，优先保证信息层级和交互一致，特效可以简化。
